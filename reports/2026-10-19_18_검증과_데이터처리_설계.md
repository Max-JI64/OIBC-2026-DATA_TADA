# 검증과 데이터 처리 설계

작성: 2026-10-19T22:42+09:00

상태: EDA 결과와 로컬 배포 자료를 검토해 작성한 실행 전 설계안이다. 검증 표본 생성, 전처리 적용, 모델 학습, 예측과 점수 계산은 수행하지 않았다. 새 EDA도 실행하지 않았다. 이 문서의 날짜와 방법은 다음 작업의 기준안이며 실제 실행으로 적합성을 확인한 결과가 아니다.

## 질문과 목적

다음 단계에서 무엇을 어떤 자료로 학습하고 어떻게 비교할지 먼저 정한다. 데이터 처리, 모델 변경과 집합 구성 변경의 효과가 한꺼번에 섞이지 않도록 한다. 기본 EDA는 종료 상태로 유지하며, 새로 필요한 탐색은 [EDA 진행 계획](EDA_진행계획.md)에 질문과 종료 기준을 기록한 뒤 별도로 다룬다.

이번 산출물은 이 설계 문서와 연결된 작업 기록이다. 현재 세션에서는 모델을 실행하지 않는다.

## 과제와 비교 단위

배포 자료에 따르면 253개 발전소를 G1/G2 중 하나에 배정해 평가 1년간 유지하고, 집합별 시간 발전량을 예측한다. 첫 실험의 참조 구성은 `current_group`의 A를 G1, B를 G2로 대응시킨다. 이는 현재 메타를 이용한 비교용 구성이며 과거 실제 운영 배정 이력을 재현한 것이 아니다.

첫 모델은 배포 기준선처럼 여러 발전소를 함께 학습해 발전소별 발전 비율을 예측하고, 용량을 곱한 kWh를 집합별로 합산하는 구조로 계획한다. 구성은 고정한 채 예측의 차이를 먼저 비교한다. 구성 최적화는 이 설계의 최초 실험 범위 밖이다.

전체 과제의 구성 조건은 253개소의 누락/중복 없는 배정, 각 집합 20,000 kW 이상이다. 기존 검증에서 전체 용량은 42,655.370 kW였으며 참조 A/B는 이 조건을 충족했다. 실제 구현 때에는 원본 메타의 정확한 합계로 다시 검사한다. 일부 발전소의 진단용 소집단에 이 조건이 충족된다고 간주하지 않는다.

## 시간과 이용 가능 정보

`ts`는 KST 구간 종료 시각이고, 대상 날짜 D는 `s = ts - 1시간`의 날짜다. `ts=2025-01-02 00:00`인 행은 1월 1일의 23~24시 구간이므로 1월 1일 예측 묶음에 속한다. 해당 묶음의 예측 시점은 2024-12-31 17:00 KST다.

| 자료 또는 파생 정보 | 첫 실험에서의 사용 | 이유와 조건 |
|---|---|---|
| 대상 날짜의 10시/17시 라운드 예보 | 사용 계획 | 배포 README는 모두 대상일 전날 발행되며 예측 시점에 사용 가능하다고 명시한다. 대상 날짜/지점/라운드를 정확히 연결한다. |
| 발전소 메타, 달력, 제공 좌표에서 계산한 태양 위치 | 사용 계획 | 배포 기준선의 입력 범위를 따른다. 좌표의 익명화와 정적 용량을 과거에도 적용한다는 한계는 남긴다. |
| 학습 구간의 발전 실적 | 학습 목표값으로만 사용 계획 | 아래 학습 마감 전에 존재한 기록만 쓴다. 기록 부재는 목표값으로 만들지 않는다. |
| 대상일의 기상 실측 | 직접 입력에서 제외 | 학습 구간에 있어도 예측 시점에는 알 수 없고 평가 구간에는 제공되지 않는다. |
| 평가 구간의 실제 발전량, 예측일 직전 시간/전날 실적 | 첫 실험에서 제외 | 평가 1년의 실적이 없으므로 과거 검증에서만 참값을 붙여 쓰면 재현 조건이 달라진다. |
| SMP와 k | 점수 계산에 사용 계획 | 첫 모델의 입력에서는 제외한다. 제공된 평가 가격이 있다는 사실과 일반적인 예측 시점의 가격 가용성을 혼동하지 않는다. 학습 손실 가중은 후속 후보로만 둔다. |
| 전체 학습/검증/평가를 합쳐 계산한 평균, 분위수와 보정값 | 사용하지 않음 | 처리에 필요한 추정값은 해당 실험의 학습 부분에서만 계산한다. |

학습/확인 구간에서도 모델과 처리값을 각 구간 첫날 전에 고정하고 해당 구간 내 실적으로 갱신하지 않는 방식으로 설계한다. 평가 구간에 일별 실적이 들어오지 않는 현재 배포 조건을 모사하기 위해서다. 예측 날짜를 옮겨가더라도 실제 정답을 이전 날짜의 입력으로 주입하지 않는다.

## 검증 기간 설계안

기간 경계는 모두 구간 시작 s와 KST로 해석한다. 개발과 후반 확인의 역할을 구분하며 무작위 행 분할은 사용하지 않는다.

| 구분 | 예측 대상 구간 시작 s | 학습 입력/목표의 종료 시각 ts 상한 | 계획한 학습 시작 s | 역할 |
|---|---|---|---|---|
| 개발 비교 V1 | 2024-01-01 00:00 이상, 2025-01-01 00:00 미만 | 2023-12-31 00:00 KST 이하 | 2022-01-01 00:00 KST | 두 처리안의 1년 비교. 한 번 적합한 모델을 유지하고 분기/월 결과를 진단한다. |
| 후반 확인 V2 | 2025-01-01 00:00 이상, 2025-06-01 00:00 미만 | 2024-12-31 00:00 KST 이하 | 2023-01-01 00:00 KST | V1에서 정한 방법을 고정해 더 최근 시기에 확인한다. 전체 발전소의 공통 관측 지표를 함께 본다. |
| 최종 평가 입력 구간 | 2025-06-01 00:00 이상, 2026-06-01 00:00 미만 | 별도 최종 학습 설계에서 정함 | 미정 | 실제 발전량 정답이 없는 제공 평가 구간. 로컬 성능 비교나 후보 선택에 사용하지 않는다. |

학습 마감은 예측 구간 첫날 D의 전전날까지 끝난 시간 기록, 즉 `ts <= D-1일 00:00`으로 보수적으로 정했다. 예측 시각인 D-1일 17:00보다 앞선 완결 일자만 쓰는 설계다. 실제 수신 지연을 확인한 것은 아니며, 구현 때 확인된 가용성이 더 늦다면 마감을 더 앞당기고 기록한다. 주어진 날짜만으로 모든 시점의 실제 수신을 보장하지 않는다.

실제 데이터 경계, 해당 학습 행 수, 목표값 가용성과 예보 조인 가능성은 아직 산출하지 않았다. 구현 전 적합성 점검에서 위 경계의 행을 선택하고 검증한다. 범위를 조정해야 하면 모델 점수를 보기 전에 이유와 변경 이력을 남긴다.

V2는 앞으로의 모델 선택에 사용하지 않을 후반 확인 구간이다. 이미 EDA에서 이 기간의 데이터 특성을 봤으므로 완전히 미관찰된 독립 시험이라고 표현하지 않는다. 평가 예보의 분포도 EDA에서 살펴봤으며 기압 제외 후보의 동기가 됐다. 이 이력을 숨기지 않고, 평가 입력에 맞춰 보정값이나 모델을 반복 선택하지 않는다.

## 발전소와 목표값 가용성

학습에는 각 마감 전에 실제 목표값이 있는 발전소-시각 행을 사용한다. 발전소별 학습 행 수와 최초 기록 시각은 구현 단계에서 기록하고, 학습 행이 없는 발전소도 253개 예측 격자에서는 제외하지 않는다. 배포 기준선의 공동 학습 구조를 사용하며, 목표값이 없는 발전소의 미래 실적을 거꾸로 학습에 넣지 않는다.

| 평가 표본 | 계획한 사용 | 해석 한계 |
|---|---|---|
| 2024년 완전 기록 148개 발전소 | V1의 연간/계절 진단을 같은 발전소와 시간축에서 비교 | EDA 때 연간 가용성을 보고 선정한 사후 진단 집단이다. 전체 253개소의 대표 표본이나 실제 투입 시점에 선정된 집단이 아니다. |
| 각 구간의 개별 관측 행 | 관측 가능한 전체 발전소의 개별 오차와 학습 기록 유무별 진단 | 발전소별 관측 기간과 가중이 다르므로 누락된 실적을 포함한 전체 성능으로 해석하지 않는다. |
| V2의 253개 모두 관측된 공통 시각 | 두 집합 전체의 가중 절대오차를 같은 시각에서 비교 | 실제 공통 시각 수와 가격 가중 합을 함께 보고한다. 일부 기간/계절의 지표이며 연간 공식 점수가 아니다. |

집합의 실제 합계는 집합 안의 모든 발전소 정답이 있어야 정의한다. 모든 253개소를 비교하는 주 집합 지표는 두 집합 모두 완전한 공통 시각으로 제한한다. `sum`이 NaN을 건너뛰어 부분 합계를 만들지 못하도록 완전성 마스크를 먼저 적용한다. 없는 발전소 실적을 0이나 예측값으로 채운 합계를 정답으로 사용하지 않는다.

V1의 148개 참조 하위집단도 같은 A/B 연결을 유지해 집합 오차를 진단할 수 있지만, 그 두 부분집합은 대회 용량 조건을 만족하는 제출 구성이 아니다. 이 지표는 아래에서 `W_148_proxy`로 별도 표시한다.

모든 방법은 같은 고정 표본과 동일한 목표값/가격으로 비교한다. 특정 방법에 불리한 예보 결손이 있다고 검증 시각을 삭제하지 않는다. 정답이 없어 로컬 지표를 계산할 수 없는 경우와, 예보 결손이 있어도 예측을 생성해야 하는 경우를 구분한다.

## 비교 지표

집합 g의 실적과 예측을 각각 다음처럼 정의한다.

```text
A(g,t) = 해당 집합 발전소의 실제 energy 합계
Yhat(g,t) = 해당 집합 발전소 예측 kWh 합계
W = Σ_t Σ_g SMP(t) × k(t) × |Yhat(g,t) - A(g,t)|
R = Σ_t SMP(t) × Σ_g A(g,t)
S_local = R - 0.10 × W
```

배포 README와 로컬 설명회 정리의 식을 기준으로 한 로컬 정의다. 동일 정답/구간/구성에서는 R이 같으므로 W가 작은 방법의 로컬 정산금이 크다. 발전소별 절대오차를 합한 값과, 집합 안에서 합산한 뒤 절댓값을 취한 값은 구분한다. G1/G2를 합친 뒤 하나의 절댓값을 취하지 않는다.

배포 폴더에는 기준선 주석이 언급하는 문제정의서와 scoring.py가 없었다. 따라서 이 설계가 공식 채점기와의 동치 검증을 완료했다는 뜻은 아니다. 구현 시 확보된 정본과 대조하고, 현재 자료만으로 계산했다면 결과 이름을 로컬 W/S로 유지한다.

| 지표 | 역할 |
|---|---|
| 전체 253개 공통 시각의 W와 S_local | 대회 과제에 가까운 주 확인 지표. 사용 시각 수, 가격 가중 합과 기간을 반드시 붙인다. |
| W / (2 × Σ_t SMP(t) × k(t)) | 같은 의미의 집합별 가중 MAE, kWh 단위. 기간이 달라질 때 참고하지만 표본 차이가 사라지는 것은 아니다. 분모가 0이면 정의하지 않는다. |
| W_148_proxy | V1의 고정 148개 참조 하위집단에서 계산한 개발용 대리지표. 공식 점수나 적법한 제출 구성 성능으로 표현하지 않는다. |
| 발전소별 cf MAE, kWh MAE와 편향 | 오차가 커지는 발전소와 정규화 효과를 진단한다. 대회 목표를 대체하는 최종 지표로 쓰지 않는다. |
| 월/분기, k=3/1, 낮/야간, 목표값 가용성별 결과 | 개선이 한 조건에만 몰렸는지 확인한다. 이 분할을 보고 실험을 무제한 추가하지 않는다. |

학습 가격은 `train/smp.csv`를 시간 키당 하나로 조인한다. k는 타임존을 KST로 맞춘 종료 시각 `ts.hour`가 11~15일 때 3, 나머지 1로 만든다. 최종 평가 격자에서는 제공 k를 사용한다. 정확히 SMP=0인 시각은 W 가중치가 0이지만 예측 격자에서 삭제하지 않는다. 가중이 없는 MAE도 함께 보면 그 시각의 예측이 가려지는 것을 줄일 수 있다.

정답의 음수/큰 값을 점수 계산에서 임의로 자르지 않는다. 아래 기준선의 학습 목표 변환은 학습용이며 점수의 정답을 바꾸는 처리가 아니다.

### V1에서의 선택 규칙

1. 같은 고정 표본의 W_148_proxy를 개발용 주 대리지표로 사용하고, 발전소별 오차와 분기별 방향을 함께 기록한다. 이 선택의 한계는 148개 집단의 구성/관측 편향이다.
2. B1의 개발 대리지표가 개선되지 않으면 이 비교에서 개선됐다고 보고하지 않는다. 전체가 좋아져도 네 분기 중 하나가 B0 대비 5%를 넘게 악화하면 자동 채택하지 않고 불안정 후보로 남긴다. 분기별 B0의 W가 0이면 상대 비율 대신 원값과 절대 차이를 기록한다.
3. 5%는 이번 계획의 운영용 문턱이며 통계적 유의성이나 정상 변동 범위가 아니다. 동률 또는 판단이 불명확하면 B0를 비교 기준으로 유지한다. 기압의 분포 변화 위험은 점수와 별도의 남은 한계로 기록한다.
4. V2의 전체 발전소 지표가 개발 대리지표와 반대 방향이면 그 불일치를 보고한다. V2를 새 튜닝 구간으로 돌려 후보를 계속 고르지 않는다. 이 경우 후속 실행 계획을 따로 작성하며 최종 방법이 검증됐다고 주장하지 않는다.

기압 제외가 실제로 좋을지는 아직 알 수 없다. 개발에서의 개선이 평가 구간의 자료 변화를 해결했다는 증거도 아니다. 모델 점수나 생산용 변수 선택은 현재 확정하지 않았다.

## 이후 작업의 기록과 전환 기준

미래 실행을 시작할 때 실험마다 ID, 목적, 코드 버전, 입력 해시, 기간과 마감, 표본/가격 가중 합, 구성, 특징 목록, 처리값을 적합한 범위, 설정/난수, 실제 실행 여부, 점수와 판단을 기록한다. 데이터와 개별 예측/잔차/정답 출력은 로컬 data/에 두고, 코드와 요약 보고서만 커밋한다.

S0에서 새 자료 문제가 발견되면 해당 구현을 고치는 점검인지, 독립적인 추가 EDA인지 먼저 구분한다. 새 EDA라면 기존 계획에 질문과 범위, 종료 기준을 기록하고 우선순위를 검토한다. 이 설계 문서 작성으로 EDA 후보가 자동으로 필수 작업으로 바뀌지는 않는다.

현재 작성 완료 범위는 다음과 같다.

- 예측 시점과 이용 가능 정보, V1/V2 기간 및 시점 마감의 설계안을 정했다.
- 부분집합 진단과 전체 집합 지표, 처리 기준안과 후속 후보를 구분했다.
- 두 설정만 비교하는 최초 실험과 종료 기준을 기록했다.
- 자료 조인, 표본 생성, 전처리 적용, 모델 실행, 점수 계산과 제출은 아직 하지 않았다.

다음 실제 실행 작업은 S0의 구현 점검이다. 현재 요청은 설계 문서 작성이므로 이번에는 S0도 실행하지 않는다.
