# CSV 제외와 커밋 이력 점검

점검일: 2026-10-21 KST. 저장소 관리 점검이며 새 EDA나 모델 실험은 수행하지 않았다.

## 요청과 점검 범위

원본, 전처리 결과뿐 아니라 집계표와 예측 파일을 포함한 모든 CSV를 Git에서 제외하고, 이미 GitHub에 올라간 CSV가 있다면 커밋 이력에서도 제거하는 요청을 확인했다. CSV 내용은 읽거나 수정하지 않고 경로와 Git 추적 여부만 검사했다.

## 수행 방법

1. `git fetch --prune origin`으로 원격 상태를 가져오고 원격 브랜치와 태그를 조회했다. 원격에서 광고한 브랜치는 `main` 하나였고 태그는 없었다.
2. 로컬 브랜치, 가져온 원격 브랜치와 태그에서 도달 가능한 커밋 38개의 파일 목록을 각각 조회했다. 확장자는 대소문자를 구분하지 않고 검사했다.
3. 로컬 CSV 파일 경로 173개를 수집해 실제 Git 제외 규칙과 대조했다.
4. 기존 CSV 제외 패턴을 `.gitignore` 마지막으로 옮기고, 분석 집계와 제출용 CSV도 제외한다는 설명을 추가했다.

## 결과와 조치

| 항목 | 확인 결과 |
|---|---:|
| 현재 Git 추적 대상 CSV | 0개 |
| 검사한 과거 커밋 | 38개 |
| 검사한 커밋에 포함된 CSV 경로 | 0개 |
| 로컬 CSV | 173개 |
| 제외 규칙이 적용되지 않은 로컬 CSV | 0개 |

원격 `main`은 점검 당시 `7a81d6862d3d8066285c15730a2e0136f900ffd1`이었다. 검사한 이력에는 삭제 대상 CSV가 없어 이력 재작성이나 강제 푸시는 하지 않았다. 로컬 CSV는 모두 보존했다. 이번 규칙과 기록 변경은 로컬에만 커밋하며 푸시하지 않는다.

## 한계

확인 범위는 조회 가능한 브랜치와 태그의 커밋 이력이다. 이미 삭제된 원격 참조, GitHub 캐시, 외부 복제본까지 삭제되었다고 확인한 것은 아니다. 특정 과거 CSV URL이 별도로 제시되면 해당 위치를 추가로 확인해야 한다.
