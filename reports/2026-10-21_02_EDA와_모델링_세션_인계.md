# 추가 EDA와 모델링 세션 인계

작성: 2026-10-21 KST

상태: 사용자 요청에 따른 인계 설계와 시작 프롬프트 작성 완료. 이번 작업에서는 새 EDA, 통계 계산, 예측 생성과 모델 학습을 실행하지 않았다. 두 후속 세션은 사용자가 순서대로 시작한다.

## 목적과 세션 구분

대회의 목표는 하루전 발전량 예측과 발전소 두 집합 구성을 통해 로컬 정산식 S=R-0.10W를 개선하는 것이다. 현재는 참조 구성을 유지한 예측 개선 단계다. 이번 인계는 “어떤 예보 조건에서 발전량과 집합 오차의 패턴이 나타나는가”를 확인하고 검증 가능한 모델 개선안으로 연결하기 위한 것이다. 발전소 집합 재배정은 별도 작업이다.

| 순서 | 담당 세션 | 수행 범위 | 종료 시점 |
|---|---|---|---|
| 1 | 추가 EDA와 개선 가설 | 기존 저장 예측의 조건별 잔차, 반복 여부, 예측 시점의 입력 가용성을 확인하고 가설을 정리 | 실행 보고서와 모델링 인계 문서를 완성하고 로컬 커밋. 모델 학습으로 넘어가지 않음 |
| 2 | 모델링 | 완료된 EDA 근거에서 우선 가설을 골라 실험 계약을 고정하고 B3와 비교 | 제한된 실험과 저장 검증, 판단 보고서 및 로컬 커밋. 제출 단계로 넘어가지 않음 |

시작할 때 각각 [EDA 세션 프롬프트](prompts/2026-10-21_EDA와_개선가설_시작.md), [모델링 세션 프롬프트](prompts/2026-10-21_모델링_시작.md)의 본문을 새 세션에 붙여 넣는다. 모델링 프롬프트는 EDA 완료 후에 사용한다. 이 문서의 과거 수치보다 후속 보고서와 현재 파일의 검증 결과가 우선한다.

## 현재 확인한 사실

현재 우선 참조는 B3다. B3는 10시/17시 예보를 공동 입력한 LightGBM L1 모델로, 기상 30개와 태양/달력/메타 9개 특징을 쓴다. 용량 대비 발전 비율을 학습하며 기압 두 열을 포함한다. 월별 평균 잔차를 이용한 고정 보정은 없다.

| 근거 | 실제 결과와 해석 |
|---|---|
| 기본 기상 EDA | 운량/강수/습도와 발전 비율의 음의 관계, UV와 양의 관계를 확인했다. 조건별 예측 오차의 반복과 독립 기여까지 확인한 결과는 아니다. |
| B5/B6 비교 P-001 | 용량 가중 B5는 B3 대비 T0 연간 W -1.1008%, V1 -1.6822%로 초기 기준을 통과했다. 가격/시간대까지 가중한 B6는 T0에서 악화해 미채택했다. |
| 후반기 순차 검증 P-004 | B5는 R3 224개소에서 W -2.7693%, R4 252개소에서 +0.0809%였다. 두 분기 각각 개선 기준을 미통과해 B3로 복귀했다. 작은 R4 차이가 통계적 열세를 입증하지는 않는다. |
| R4 사전 진단 | 기존 148개소 소집합은 개선, 추가 104개소 소집합은 악화했다. G1은 개선, G2는 악화했다. 소집합 W를 더해 전체 W나 인과 원인을 설명할 수는 없다. |
| 아직 미확인 | 예보 조건별 과대/과소 오차의 반복, 예보 불일치의 추가 설명력, 해당 근거를 반영한 특징의 실제 성능 개선 |

현재 모델에 기상 변수가 들어 있다는 사실과 EDA에서 발견한 조건을 모델이 충분히 학습했다는 증거를 구분한다. 급변/저발전의 발생과 지속은 조사했지만 운영 장애 등의 원인은 미확정이며, 발생 조건을 예측하는 별도 모델은 없다.

## EDA 세션의 질문과 범위

P-002에 대응하는 EDA-011을 후보로 등록했다. EDA-004는 발전량 자체의 기상 조건별 공동 변동 질문이지만, EDA-011은 저장 모델의 조건별 잔차와 개선 가설을 다루므로 별도로 둔다. 기본 EDA 완료와 기존 선택 3개/보류 5개는 유지한다. 실행 세션에서 범위와 종료 기준을 확인하고 EDA-011만 진행으로 바꾼다.

핵심 질문은 “예측 시점에 알 수 있는 흐림/강수와 예보 불일치 조건에서 집합 과대/과소 오차가 반복되며, 현재 모델의 어떤 부족을 시사하는가?”다. R3/R4의 B3 잔차를 중심으로 B5 차이를 함께 보고, 기존 148개소와 추가 완전 관측 표본 및 G1/G2를 구분한다. 조건의 재현 점검은 T0/V1의 기존 저장 예측에서 정한 한 차례 범위로 제한한다. 이미 본 기간이므로 독립 검증이라고 표현하지 않는다.

실행 전에 조건 정의, 구간 경계, 분석 시간, 표본/가중 단위, 결측 분류와 작은 표본의 해석 기준을 적는다. 운량/강수, 두 라운드 차이와 A/B 제공사 차이를 우선으로 삼되 전 변수 조합 탐색으로 확장하지 않는다. 예보의 단위/강수 정의가 다르면 차이값을 만들기 전에 대조 가능성을 확인한다. 계절/시간/태양고도를 고려해 단순 일변화와 조건 관계를 구분한다.

같은 발전소-시각에서 실제 발전 비율, 예측 비율과 잔차를 함께 보고 조건별 자료량/고유 날짜/발전소/기상 지점의 지지 범위를 기록한다. 실제 발전량 또는 잔차로 정의한 사후 사건은 진단용이라고 표시하며 예측 입력으로 사용하지 않는다. 미래 입력 후보는 예보와 예측 시각 이전 정보만으로 계산할 수 있어야 한다.

집합 주 지표는 W=Σ(g,t) SMP(t)×k(t)×|Σ(i∈g)e(i,t)|다. e=예측-정답, k는 KST 종료 시각 11~15시에 3, 나머지는 1이다. 구성과 정답을 고정하고 그룹 사이 잔차를 먼저 합치지 않는다. 개별 발전소의 조건별 절대오차 합은 집합 W와 다르다. 발전소별 날씨 조건으로 집합을 나눠 계산한 부분 W도 일반적으로 전체 W에 더해지지 않는다. 집합 W의 조건 분해에는 집합-시각의 조건 정의를 먼저 정하거나 합계가 보존되는 부호 있는 잔차 기여를 사용하고 직접 합계를 검증한다.

조건을 바꿔가며 검증 W가 가장 좋아지는 경계를 고르지 않는다. 모델에 넘길 경계/평균/분위수/정규화는 학습 마감 이전 자료에서만 추정할 수 있는 계산 규칙으로 정의한다. 동일 기상 지점의 발전소별 반복과 시간 의존성을 독립 표본 수로 세지 않는다. EDA 상관이나 조건별 평균 차이를 인과 효과로 표현하지 않는다.

## EDA 종료와 모델링 인계 문서

실행 날짜의 독립 보고서 `reports/YYYY-MM-DD_NN_예보조건별_잔차_EDA.md`를 만들고, 안정된 인계 경로 `reports/EDA_개선가설_모델링_인계.md`를 EDA 완료 시 생성한다. 이 두 결과물은 현재 아직 생성되지 않았다. 모델링 세션은 두 번째 파일을 진입점으로 삼는다.

인계 문서에는 다음 내용을 빠짐없이 남긴다.

1. 완료/부분 완료 상태, 작성 시각, 실행 보고서/코드/로컬 검증 산출물 링크와 입력/코드 해시 근거.
2. 실제 사용한 기간/고정 표본/예측 출처, 조건 정의와 가용성, 결측/가중/집합 계산 방식.
3. 조건별 실제 발전량과 예측 오차의 확인 사실, 반복된 범위, 반복되지 않은 결과와 불확실성. 조건과 오류의 단순 동반 변화도 구분.
4. 가설 최대 3개. 각 가설에 ID, 관측 근거, 현재 특징에 이미 포함된 정보, 새로 바꿀 내용, 예측 시점 가용성, 기대 효과와 실패 조건을 기재. 가장 먼저 시험할 가설 1개 또는 근거 부족에 따른 보류 판단.
5. 후보 특징의 정확한 식/단위/결측 처리와 학습 내 적합 규칙. 실측이나 대상일의 미래 발전량을 요구하는 아이디어는 실행 후보에서 제외.
6. 모델링 제안 계약: B3 참조, 변경 축, 사용 기간/표본, 선택에 쓰는 지표, 관측한 개발 자료의 재사용 한계와 제한된 적합 예산. 제안과 실행 결과를 혼동하지 않음.
7. 최종 상태를 `모델링 가능` 또는 `모델링 보류`로 명시하고 근거를 적는다. 통계적 패턴이 약하면 가설을 억지로 만들지 않는다.

조건별 잔차 점검과 미리 정한 반복 확인 한 차례, 근거표/그림 검증과 가설 인계로 종료한다. 새 독립 질문은 후보에 남기며 연속 심화로 범위를 늘리지 않는다. 학습/튜닝/새 추론/검증 잔차 보정 계수 적합/집합 재배정은 EDA 세션에서 하지 않는다.

## 모델링 세션의 시작과 판단

EDA 인계 파일의 실제 완료 상태와 연결된 실행 보고서를 먼저 확인한다. 인계 파일이 없거나 모델링 보류이면 아직 분석하지 않은 조건이나 가설을 임의로 보충해 학습하지 않는다. 확인 가능한 누락을 점검하고 선행 EDA의 미완료 항목을 사용자에게 구체적으로 알린다.

모델링 가능이면 최우선 가설 1개를 기본 범위로 삼는다. 실험 ID와 정확한 입력/특징/학습 마감/참조 계약/표본/선택 기준/적합 예산을 점수 확인 전에 별도 보고서와 성능 계획에 고정한다. EDA 제안 계약을 실행 가능한 계약으로 정리하는 일은 모델링 세션의 책임이다. 결과가 좋지 않다는 이유로 조건, 기간, 표본이나 한도를 사후 변경하지 않는다.

기본 비교는 기존 T0/V1/R3/R4의 같은 학습 경계와 고정 표본을 사용한다. B3의 저장 예측이 계약과 일치하면 재사용하고, 다른 학습 경계를 적용하면 동일 경계의 참조 모델이 필요하다. 최초 후보는 4구간 각 1회로 기본 4회 적합, 참조 재적합이 꼭 필요한 경우에는 사유와 최대 8회 예산을 사전에 기록한다. 한 실험에서 여러 가설이나 무제한 설정 탐색을 섞지 않는다.

기본 채택 기준은 T0/V1 연간 W가 각각 감소, 연간 표본의 어느 분기도 5% 초과 악화 없음, R3/R4 분기 W가 각각 감소 및 어느 월도 5% 초과 악화 없음이다. 상대 동률 허용오차 1e-12를 유지한다. 이는 개발 선택 규칙이고 통계적 유의성 기준은 아니다. 가설에 맞춰 다른 계약이 필요하면 실행 전에 변경 이유와 기준을 기록한다. 실제 비교를 마친 뒤 기준을 바꾸지는 않는다.

우선 확인한 조건에서 오차가 줄어도 전체 집합 W가 나빠지면 개선으로 채택하지 않는다. 동일 표본의 전체/월/분기/집합/k와 EDA 조건별 결과를 함께 남기고 전체 253개소의 짧은 공통 표본은 별도 진단한다. 어느 후보도 통과하지 못하면 B3를 유지하고 그 결과로 종료한다.

## 두 세션의 공통 실행과 보존

- 원본과 기존 모델/예측/보고서를 보존한다. V2는 과거 B0에서 한 번 확인한 자료이며 새 후보 선택/튜닝에 다시 쓰지 않는다. 정답 없는 제공 평가 구간도 새 후보 진단이나 예측 재생성에 사용하지 않는다.
- 같은 2023~2024년을 다시 나눈 결과를 독립 미래 시험으로 부르지 않는다. 공식 scoring.py와 문제정의서가 없어 로컬 채점의 공식 구현 동치는 미확인이다.
- 정규 CPython 3.13 실행은 AGENTS.md의 최초부터 승격된 PowerShell Start-Process 경로를 따른다. 기본 sandbox에서 Python을 시험 실행하거나 다른 런타임으로 우회하지 않는다.
- LightGBM 네이티브 모델은 한글 경로의 직접 저장/로드 대신 기존 문자열 직렬화 방식을 유지한다. 장기 실행은 완료 요약과 저장 검증을 남기며 대화 중단 뒤 완료 모델을 자동 재적합하지 않는다.
- 실행 날짜의 보고서와 일별 로그, 필요 시 LOG.md, AGENT_MEMORY.md의 짧은 현재 상태를 갱신한다. 코드/보고서/필요한 문서만 명시적으로 스테이징해 한국 날짜의 로컬 커밋을 한다. 모든 CSV와 데이터 출력은 제외한다. push와 공식 제출은 하지 않으며 커밋 뒤 추가 확인 명령은 실행하지 않는다.

## 이번 문서 작업의 확인 범위

관련 계획과 핵심 코드의 읽기 검토로 인계 내용을 작성했다. EDA-011은 다음 세션용 후보로만 등록했다. 링크/필수 항목/금지 기호와 스테이징 범위를 정적으로 확인하며 이를 분석 실행이나 성능 검증으로 표현하지 않는다.
