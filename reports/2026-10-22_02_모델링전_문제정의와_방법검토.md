# 모델링 전 문제 정의와 방법 검토

작성: 2026-10-22 KST. 작업 ID: P-007. 상태: 기존 근거/방법 검토와 합성 점검 10개 완료. 예측 모델 학습/추론 0회.

**판단:** 당장 바꿔야 할 것으로 확인된 것은 모델 종류보다 실험 해석과 실행 계약이다. B3를 유지하고 P-006은 조건부 비교 후보로 남긴다. ID 추가가 최선이라는 증거는 없으며, 개별 손실과 집합 W의 불일치도 이 후보 하나로 해결되지 않는다. 이번 점검으로 실제 성능이 더 좋은 방법을 선정한 것은 아니다.

## 질문과 목적

사용자는 P-006 모델링 착수 전에 현재 문제, 더 나은 방법, 개선 순서와 피해야 할 위험을 먼저 분석하고 실험하도록 요청했다. 앞선 설계 종합에서 제안한 ID 추가를 확정안으로 취급하지 않고 대안과 비교한다. 이번 실험은 방법상 반례와 구현 계약을 확인하는 합성 점검이며 발전량 예측 성능 비교가 아니다.

## 사용 범위와 사전 종료 기준

- 기존 EDA/DA 보고서, B3/B5/B6/H1 기록과 실제 코드, 공식 라이브러리 문서와 원저자 방법 자료를 읽는다.
- 원본 발전량/기상 행, 저장 예측의 새 분석이나 점수 계산은 하지 않는다. V2와 제공 평가 자료를 재평가하지 않는다.
- 합성 사례 10개로 개별 손실과 집합 W의 순위, 소집합 비가산성, 중앙값 합산, 목표/출력 처리, 시간 경계/겹침, 학습 범주 제한, 범주 코드 정렬, 기존 39열 보존, 미관측 ID 처리와 범주 메타데이터 저장을 확인한다.
- 기존 생산 코드의 순수 함수와 설치된 LightGBM의 pandas 변환 함수를 합성 입력에만 호출한다. 예측모형 적합, Booster 로드, 모델 추론과 예측 파일 생성은 0회로 제한한다. 범주 메타데이터의 왕복 확인을 학습 모델의 저장/추론 동치로 표현하지 않는다.
- 실패는 오류와 주장 반례를 구분해 기록한다. 합성 반례가 예상대로 나타나면 해당 위험이 가능함을 확인한 것이며 실제 B3에서 그 원인이 발생한다는 증거가 아니다.
- 대안별 근거와 비용, 기존 실험 중복 여부, 실행 전 차단 조건, 후속 후보 하나의 조건부 판단을 남기면 종료한다. 새 독립 데이터 분석을 연이어 시작하지 않는다.

## 1. 현재 마주친 문제

### 학습하는 오차와 최종 판단하는 오차가 다르다

B3는 낮 관측 행의 CF=energy/cap을 [0, 1.2]로 자른 뒤 행별 동일 비중의 L1을 학습한다. 평가는 원래 발전량에서 집합별 잔차를 합산한 다음 절댓값을 취한다. [목표/출력 함수](../scripts/b0_v1_baseline.py#L60)와 [집합 점수](../scripts/validation_core.py#L150)에서 확인했다.

집합 잔차 e를 원래 kWh 기준으로 쓰면, q=SMP×k가 비음수일 때 다음 관계가 성립한다.

```text
W = Σ(t,g) q(t) |Σ(i∈g) e(i,t)|
U = Σ(t,g) q(t) Σ(i∈g) |e(i,t)|
W <= U
```

U를 줄였다고 W도 반드시 줄지는 않는다. 용량/가격 가중을 주면 집합 합산 손실과 같아진다는 설명은 잘못이다. 또한 위 U는 원래 정답과 후처리된 예측을 기준으로 한 수학적 상한이다. 목표 clip과 야간 처리 때문에 B6의 실제 학습 손실과 U가 항상 같다고 할 수도 없다.

이 간격을 줄이려는 B5/B6는 이미 시험했다. B5는 T0/V1 연간 W가 -1.1008%/-1.6822%였으나 후반기 R3 -2.7693%, R4 +0.0809%로 기존 기준을 통과하지 못했다. B6도 T0 +0.5650%로 미채택됐다. 이는 특정 실험의 결과이며 모든 가중 학습이 불가능하다는 뜻은 아니다. 동일한 가중안을 새 개선안처럼 반복할 근거는 없다. [가중치 비교](2026-10-20_10_B5_B6_학습가중치_비교.md), [후반기 비교](2026-10-20_11_B3_B5_후반기_순차검증.md).

### 설명 분석에서 찾은 차이가 B3의 미학습 오차인지는 확인하지 못했다

DA-002는 80개소의 곡선 형태 차이를 확인했다. 현재 B3에는 hour, 태양기하, 계절, cap/lat/lon과 A/B 두 라운드 기상이 이미 있다. 곡선 차이가 있다는 것과 그 차이를 B3가 놓친다는 것은 다른 주장이다. ID가 이 정보를 더 쉽게 표현할 수는 있지만 기존 특징이 충분할 수도 있다. DA-012는 두 유형의 일관된 기상 반응 차이를 확보하지 못했으므로 유형별 분리의 근거가 되지 않는다. [최신 종합의 적용 범위와 반영 상태](2026-10-22_01_분석결과_종합과_현재모델_설계점검.md).

H1에는 B3 잔차의 반복되는 조건 대비라는 더 직접적인 근거가 있었지만 T0/V1 -0.3226%/-0.2678%, R3/R4 +1.0200%/+0.9358%로 실패했다. 따라서 관측 관계를 발견하면 특징을 추가하는 절차만으로는 충분하지 않다. [H1 결과](2026-10-21_04_H1_운량_태양계절_교차특징_비교.md).

모든 구간의 예보 발행 기준부터 종료 ts까지는 코드상 8~31시간이다. 그러나 고정 학습 마감 이후 경과 시간은 R3/R4에서 최대 2,232시간, V1에서 8,808시간, 보존된 최종 설계에서 8,784시간이다. 이는 예보 선행시간과 모델에 반영된 발전량 자료의 최신성이 서로 다른 축임을 뜻한다. R3/R4 통과만으로 1년 고정 운용을 확인했다고 할 수 없으므로 연간 비교도 유지한다. 최종 설계의 날짜 계산만 했으며 평가 데이터나 예측은 읽지 않았다. [시간 계약](../scripts/validation_core.py#L32), [순차 구간](../scripts/b5_rolling_compare.py#L24), [최종 설계](../scripts/b3_final_design_check.py#L18).

시간 순서를 지킨 분할도 반복 선택에 쓰면 선택 편향이 남는다. 새 분할을 기존 자료에 만들었다는 이유로 미관찰 시험이 되지는 않는다. 이를 줄이는 당장의 조치는 한 후보/한 변경 축/사전 기준/제한 예산이며 V2를 재사용하는 것이 아니다. [Forecasting: Principles and Practice, 시간 교차 검증](https://otexts.com/fpp3/toolbox.html#time-series-cross-validation).

발전소 간 차이가 있어도 공유 모델을 반드시 나눌 필요는 없다. 전역/개별 시계열 방법의 표현 가능성을 다룬 연구도 그 가능성을 설명하지만, 특정 B3와 P-006 중 어느 쪽이 나은지는 답하지 않는다. 이 연구의 이론을 현재 600트리 모델이 충분하다는 증명으로 쓰지 않았다. [Montero-Manso와 Hyndman 원문](https://arxiv.org/abs/2008.00444).

집합 손실은 구조적으로 매력적이지만 단순 가중치 교체와 다르다. 예를 들어 매끄럽게 근사한 집합 손실 phi(Σ cap_i×CF오차_i)의 Hessian에는 같은 집합-시각 행 사이의 교차항이 생긴다. LightGBM 사용자 목적함수 API의 행별 grad/hess 배열에 대각값만 넣는다고 이 결합 목적의 최적화가 정확해지지는 않는다. 근사 방법과 집합 단위 표본 구성의 별도 검증이 필요하다. 이는 수식과 API에 근거한 설계 판단이며 구현 불가능하다는 주장도 아니다. [LightGBM 4.6.0 사용자 목적함수 계약](https://lightgbm.readthedocs.io/en/v4.6.0/pythonapi/lightgbm.LGBMRegressor.html).

테스트는 실제 `local_score`, `target_values`, `prediction_values`, `Window.training`, `clock`을 합성 입력으로 호출했다. 날짜는 실행 코드의 Window 리터럴에서 추출했다. LightGBM private pandas 변환/메타데이터 함수를 설치 버전 4.6.0에 한정해 점검했으며 이를 생산 코드 의존성으로 채택하지 않는다. 생산 구현은 공개 categorical_feature 계약을 사용해야 한다.

실행 중 pandas CSV/Parquet 읽기, LightGBM fit/train/cv, Booster 생성/추론 경로를 오류로 차단했고 호출은 없었다. 생성한 것은 점검 요약 JSON과 사전 문서 사본뿐이다. 데이터 행 읽기 0회, 발전량 예측모형 적합/추론 0회, 예측 파일 생성 0회다. 라이브러리 import와 합성 출력 후처리를 모델 추론으로 세지 않는다. 실행 전후 점검 대상 코드 해시는 동일했다.

## 4. 피해야 할 위험과 실행 전 보완

| 위험 | 실행 전에 정할 처리 | 중단/보류 조건 |
|---|---|---|
| 설명 분석의 유형이나 평균을 미래 정답까지 사용해 입력으로 전달 | ID만 사용하고 범주 사전은 각 구간의 마감 이전 낮 학습 행에서 고정 | 미래 정답/유형/타깃 평균이 인코딩에 들어가면 중단 |
| ID를 숫자 크기로 학습하거나 40열 전체를 float32로 변환 | 기존 39열 float32 + 명시적 비순서 범주 1열, 실제 fit의 categorical_feature와 저장 스키마 확인 | 범주 선언 누락, 원래 값/순서/NaN 변경 시 중단 |
| 짧은 기록 과적합, 새 ID의 성능 과신 | 학습 ID별 낮 행 수, 월 범위, 주 표본의 학습 관측/미관측 분포를 점수 전 가용성으로 기록 | 단순 추론 가능 여부를 미관측 성능 검증으로 표현하지 않음. 새 ID 정답이 부족하면 미검증으로 남김 |
| 미관측 ID의 결측 처리를 안전한 B3 대체로 착각 | 후보 모델의 결측 분기로 처리한다는 뜻만 명시 | B3 fallback을 보장해야 한다면 별도 정책/비교 계약이 필요. P-006에 조용히 추가하지 않음 |
| 범주 기본 정규화의 우연한 변경 | 설치 버전과 cat_smooth=10, cat_l2=10, min_data_per_group=100, max_cat_threshold=32, max_cat_to_onehot=4를 기록하고 탐색하지 않음 | 버전/유효 설정이 다르면 참조 계약 검토 전 적합 중단 |
| ID의 순수 정보 효과로 과해석 | colsample_bytree=0.8에서 열 추가가 특징 추출 경로도 바꾼다고 기록 | 단일 비교로 ID의 인과 기여나 통계적 유의성 주장 금지 |
| 기간/표본이나 채택 기준을 결과에 맞춰 변경 | T0/V1/R3/R4의 같은 참조/정답/가격/구성, 기존 4조건을 결과 전에 고정 | 일부 조건 개선만으로 실패한 주 기준을 뒤집지 않음 |
| 짧은 전체 표본이나 완전 관측 소집합을 전체 253개 연간으로 일반화 | common_253의 가용 시간과 주 표본의 구성 차이를 함께 보고 | 표본 부족을 0오차나 일반화 성공으로 표현하지 않음 |
| lag 특징과 재학습에 미래 실적 사용 | 예측 발행 시각 이전 관측만 사용 가능하다고 정의. 이번 후보에는 lag 추가 없음 | 모든 대상 시각에서 t-24가 전일 17시보다 이르다고 가정하면 안 됨 |
| 저장 B3나 기존 실험 코드 무검토 재사용 | 참조의 원본/환경/모델 설정/학습 경계/행/특징 계약을 확인하고 새 사전 사본 생성 | 불일치 시 자동 참조 재학습, 예산 증액 또는 보호 검사 삭제 금지 |

LightGBM 공식 문서는 범주 입력과 작은 범주의 과적합 제어를 설명한다. 문서에 있는 고카디널리티 수치 표현 가능성이 익명 site_id의 숫자 순서를 이 문제에 적합하게 만든다는 뜻은 아니다. 이번에는 임의 순서를 도입하지 않는 명목 범주 비교로 한정한다. [범주/결측 처리](https://lightgbm.readthedocs.io/en/v4.6.0/Advanced-Topics.html), [범주 설정과 특징 추출](https://lightgbm.readthedocs.io/en/v4.6.0/Parameters.html).

현재 [H1 protected 함수](../scripts/h1_cloud_interaction.py#L70)는 과거 EDA의 문서/출력 해시와 인계 문구까지 요구한다. 문서가 후속 분석으로 갱신된 현재 P-006에 이 함수를 그대로 붙이는 것은 적합하지 않다. 참조 모델/데이터/코드의 동일성은 검증하고, 현재 계획/보고서의 동결 목록은 새로 만들어야 한다. 이 판단은 코드 읽기 결과이며 이번에 기존 보호 검사를 실행하거나 수정하지 않았다.

## 5. 다음에 할 일과 실행 판단

우선 해야 할 일은 모델 종류를 바꾸는 것이 아니라 P-006의 실행 계약을 위 위험까지 포함해 완성하는 것이다. 현재 근거에서는 이를 대체할 더 좋은 성능 방법을 확정하지 못했다. 따라서 후속 실제 비교 후보는 여전히 **공유 B3 + 명목 ID 1열** 하나로 제한하되, 결함 수정이 아닌 불확실한 표현 가설로 취급한다.

실행 단계는 다음과 같이 구분한다.

1. **가용성/계약 점검:** 저장 B3 계약 일치, 구간별 낮 학습 ID 사전/관측 길이/미관측 범위, 실제 39+1열 스키마, 명시적 범주 지정, 기존 출력/격자 보존을 먼저 확인한다. 이번 합성 점검이 실제 입력 연결 검사를 대체하지 않는다.
2. **고정 비교:** 계약이 맞을 때 후보만 T0/V1/R3/R4 각 1회, 총 4회. 참조 재학습, 정규화 탐색, 가중 손실, 별도 fallback이나 앙상블을 함께 시험하지 않는다.
3. **판단:** T0/V1 연간 W가 각각 엄격히 감소하고 어느 분기도 5% 초과 악화하지 않아야 한다. R3/R4 전체 W도 각각 감소하고 어느 월도 5% 초과 악화하지 않아야 한다. 동률 rtol=1e-12/atol=0, 하나라도 미통과하면 B3 유지다. 5%는 기존 운영 기준이며 유의성 기준이 아니다.
4. **저장 검증:** 실제 학습 모델의 범주 사전/40열/트리 수와 재로드 예측 동치, 같은 정답에서 점수와 판단 재현까지 확인한다. 여기까지 완료해도 개발 후보로만 평가하며 전체 대상 미래 개선으로 확정하지 않는다.

부분 풀링과 집합 손실은 해결하려는 문제가 더 직접적일 수 있지만 새로운 추정/출력/표본 설계가 필요하다. 이번 근거만으로 P-006 대신 곧바로 실행하거나 새로운 필수 분석으로 올리지 않는다. P-006이 실패하면 그 결과를 검토한 뒤 P-003 등 기존 후보의 우선순위를 다시 판단하며 자동 탐색으로 넘어가지 않는다.

이번 사용자 지시는 모델링 전 검토와 실험을 먼저 하라는 요청이므로 P-007의 사전 점검으로 종료했다. P-006의 실제 학습은 미착수다. 기존 B3와 과거 평가 산출물은 변경하지 않았고 V2 재평가, 새 실데이터 통계, 공식 제출과 push도 하지 않았다.
