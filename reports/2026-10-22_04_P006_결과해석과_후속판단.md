# P-006 결과 해석과 후속 판단

작성: 2026-10-22 KST. P-008 상태: 기존 결과/코드 검토 완료. P-006 개발 우선 후보를 유지한다. 최종 적용 사전 점검 P-009와 저장 예측의 안정성 검토 P-010은 미실행 후보다.

## 질문과 목적

[P-006 비교](2026-10-22_03_P006_발전소ID_범주입력_비교.md)가 끝난 뒤 사용자가 다음 방향을 자세히 분석하도록 요청했다. 무엇을 이미 확인했는지, 무엇이 최종 적용을 막는 문제인지, 추가 작업 중 어느 것이 실제 판단을 바꿀 수 있는지 구분한다.

권장 순서는 **최종 입력 계약 확인 → 필요하면 저장 예측의 안정성 검토 한 번 → 설계가 맞으면 고정 P-006의 최종 적합 준비**다. 새 모델 탐색은 현재 우선순위가 아니다. P-006의 기존 통과 판정과 최종 적용의 기술적 준비, 독립된 미래 성능 확인을 각각 구분한다.

## 사용 범위와 수행 방법

- P-006 보고서, 로컬 `summary.json`/`verification.json`, 성능 계획과 P-007 방법 검토를 읽었다.
- 기존 [B3 최종 설계](2026-10-20_06_B3_최종학습과_평가절차_설계.md), 해당 로컬 설계 요약, 최종 `fit_summary.json`과 실제 코드를 대조했다.
- B3 설계 기록의 해시에 대해 원본 메타/기준선/학습 발전량/두 학습 예보 파일 5개와 설계/시간 계약/공통 점검 코드 3개, 총 8개가 현재와 같음을 확인했다. 원본 행을 새로 집계하거나 예보 값을 탐색하지 않았다.
- 기존 보고서에 공개된 월별 W를 빼고 더해 개선액의 집중과 상쇄를 설명했다. 아래 파생 수치는 소수 둘째 자리까지 공개된 기존 집계의 산술 결과이며 새 통계 추정이 아니다.
- 범주 처리와 검증 자료 재사용에 관한 공식 문서를 참고했다. 모델 실행/수정, 새로운 성능 점수 계산, V2 재평가, 제공 평가 예측/제출은 수행하지 않았다.

5% 월/분기 한도는 기존 의사결정 규칙이다. 통계적 유의성이나 실용적으로 충분한 개선의 기준은 아니다. 결과를 본 뒤 R4의 최소 개선폭을 새로 정해 기존 통과를 취소하거나, 반대로 통과를 확실한 미래 우위로 승격하지 않는다.

## 2. 개선의 크기보다 분포를 함께 봐야 하는 이유

R3는 7월/8월/9월이 모두 개선됐지만 크기가 다르다. 전체 감소액 18,449,995.47 중 8월 감소액이 15,500,498.95로 **약 84.01%**다. 여름 모든 달에 비슷한 효과가 난 결과가 아니며, 8월의 어떤 날짜나 오차 방향에서 차이가 났는지는 현재 월별 표만으로 확정할 수 없다.

R4는 10월에 W가 3,539,754.15 줄었지만 11~12월에는 합계 3,399,499.26 늘었다. 순감소는 140,254.90이다. 따라서 0.0307%는 단순히 모델이 거의 바뀌지 않았다는 뜻도 아니다. 월별로 반대 방향의 차이가 나면서 최종 합계가 작아졌다. 이 양상만으로 계절 과적합이나 특정 기상 원인을 확정하지 않는다.

| 구간 | 집합별 전체 W 변화 | 다음 판단에 주는 의미 |
|---|---|---|
| T0 | G1 -1.8014%, G2 -3.2859% | 양 집합의 과거 개선 근거가 있다. |
| V1 | G1 -1.6093%, G2 +0.8959% | 연간 전체 개선을 모든 집합의 개선으로 쓰면 안 된다. |
| R3 | G1 -3.3261%, G2 -2.5691% | 해당 후반기 주 표본에서는 양 집합이 개선했다. |
| R4 | G1 -0.1943%, G2 +0.1253% | 작은 순개선 안에서도 집합별 방향이 갈렸다. |

현재 주목적은 고정된 G1/G2의 비용 합이다. 집합마다 무조건 개선해야 한다는 새 조건은 추가하지 않는다. 다만 이 표를 보고 G1은 P-006, G2는 B3로 골라 쓰는 정책을 만들면 별도 후보가 된다. 월별 모델 교체나 최적 혼합 비율도 같은 문제이며 이번 결과에 조용히 덧붙일 수 없다.

V1과 R3/R4는 평가 시각이 겹치고 학습 마감과 구성은 다르다. 네 결과의 평균을 전체 개선율로 쓰거나 네 번의 독립된 성공으로 세지 않는다. R3/R4 비교는 후반기 개발 근거이며 최종 1년 고정 모델의 장기 안정성을 직접 검증한 것도 아니다. T0/V1 연간 결과는 있지만 최종 학습 마감과 전체 구성은 여전히 다르다.

## 3. 신규 ID 문제의 우선순위를 수정한다

개발 주 표본에는 학습 미관측 ID가 없었다. 전체 격자에서는 V1 미관측 105개소의 개별 MAE가 6.8934에서 6.9527kWh로, R4 미관측 1개소 178행은 22.7947에서 43.2680kWh로 증가했다. 신규 ID에 P-006의 결측 분기를 적용하는 것이 안전하다는 증거는 없다. R4 전체 공통 W 개선과 이 개별 악화는 함께 발생할 수 있다.

그러나 **기존 최종 B3 설계에는 이미 253개소 모두의 낮 학습 기록이 확인돼 있다.** 이번에 해당 설계 요약과 원본/계약 코드의 동일성을 확인했다. 같은 범위를 유지한다면 신규 ID가 최종 대상에 남을 것이라는 가정을 기본 전제로 둘 이유는 약하다.

| 기존 최종 계약과 가용성 | 저장 기록 |
|---|---|
| 대상 날짜 기준 학습 시작 | 2023-06-01 00:00 KST |
| 학습 목표 종료 시각 상한 | 2025-05-31 00:00 KST |
| 관측 학습 행 / 낮 학습 행 | 3,421,168 / 1,707,268 |
| 낮 학습 기록이 있는 발전소 | 253개소 전체 |
| 개소별 낮 학습 행 최소/최대 | 1,833 / 8,795 |
| 기존 최종 B3의 하나 이상 특징 결측 행 | 1,382 |
| 최종 평가 대상 날짜 | 2025-06-01 이상, 2026-06-01 미만 |

이는 새로운 P-006 최종 입력 행렬을 생성한 결과가 아니다. 기존 가용성 결과를 현재 동일 입력에 연결한 근거다. 후속 P-009는 처음부터 신규 ID 발생을 가정해 fallback을 개발할 작업이 아니라, 실제로 구성한 P-006의 낮 학습 ID 집합이 이 기록과 일치하는지를 확인할 작업이다.

모두 관측됐어도 1,833행과 8,795행의 정보량은 같지 않고, ID로 시간에 따라 달라지는 운영 상태까지 표현할 수 있는 것도 아니다. 이번 결과에서 임의의 최소 월 수를 정해 짧은 이력의 발전소를 B3로 전환하지 않는다. B3의 최종 기록 자체도 전체 대상에서 독립적으로 우월함을 보장하지 않는다.

## 4. 다음 우선 작업 P-009: 최종 입력 계약 확인

이 작업은 성능 실험에 앞선 적용 준비다. 적합/추론 0회를 범위로 정하고 다음 항목이 모두 맞을 때 종료한다.

| 확인 항목 | 재사용할 근거와 완료 조건 | 불일치 시 처리 |
|---|---|---|
| 학습 기간/발행 경계 | 기존 시작/마감을 유지하고 실제 ts 최소/최대와 관측/낮 행 수 대조 | 차이 원인을 기록하고 최종 적합 착수 중단. 더 좋은 기간을 찾는 탐색으로 전환하지 않음. |
| 원본과 코드 동일성 | 현재 입력/실행 코드/개발 모델의 해시와 버전을 새로운 사전 사본에 고정 | 현재 계획 문서의 수정만으로 과거 결과가 무효라고 하지 않되 입력/알고리즘 변경은 별도 판단. |
| 학습 ID와 범주 사전 | 최종 낮 학습 행에서만 정렬된 명목 사전 생성, 253개 대상과 대조 | 누락이 있으면 먼저 조인/행 선택/인코딩 오류인지 확인. 실제 미관측이 남을 때만 처리 정책 질문 등록. |
| 월별 결합과 행 대응 | 기존 관측 순서로 x/y/ID를 함께 복원하고 키/해시로 일치 확인 | 길이가 같다는 이유만으로 통과시키지 않음. |
| 39+1열 계약 | 기존 39개 float32 열/순서/NaN 유지, 마지막 열만 unordered category | 40열 전체 숫자 변환, ID 순서형 처리, 대상 메타만으로 사전 생성 금지. |
| 기상 결손 처리 | 기존 왼쪽 조인/NaN 유지와 최종 B3 결측 행 기록 대조 | 정당한 차이인지 확인 전 임의 보간/행 삭제를 하지 않음. |
| 예측 시점 사용 가능성 | 전일 10/17시 예보와 정한 학습 마감만 사용 | 최종 평가 정답/후행 자료 또는 일별 최신 실적 갱신이 필요하면 기존 계약 밖이므로 중단. |
| 실행 예산과 보존 | 새 출력 경로, 최종 적합 1회 계획, B3 파일 보호, 중단/재개 정책을 문서로 고정 | P-006 개발 실행기를 최종용으로 바꾸거나 기존 최종 B3에 덮어쓰지 않음. |

구체적인 연결 위험이 있다. [기존 최종 결합 함수](../scripts/b3_final_fit_predict.py#L30)는 모든 입력의 float32를 요구하고 x/y 인덱스를 정렬한 뒤 초기화한다. 여기에 category 열을 넣으면 dtype 검사와 충돌한다. 별도로 보관한 ID를 정렬 전 순서 그대로 나중에 붙이면 학습 행이 잘못 대응할 위험도 있다. **39열/x/y/ID를 같은 원래 행 키로 함께 정렬한 뒤 범주 열을 추가하는 연결**을 별도 최종 경로에서 검증해야 한다. 현재 코드가 잘못된 모델을 학습했다는 발견은 아니며 P-006 연결 시 피할 위험이다.

개발 [training 함수](../scripts/p006_site_category.py#L96)는 구간별 B3 참조와 H1 이력의 학습 목표 해시를 요구한다. 최종 구간에는 그 개발 참조를 그대로 쓸 수 없다. 순수 범주 변환 함수는 재사용할 수 있지만 개발용 실행 함수를 최종 구간에 억지로 호출해서는 안 된다.

최종 범위의 2025년 1~5월 실적을 고정 적합에 포함하는 것은 이미 정한 첫 예측 이전 학습이다. 이 구간에서 P-006과 B3를 새로 채점해 고르는 V2 재평가와 구분한다. 시간 경계가 맞는 최종 학습 자체를 누수로 부르거나, 반대로 최종 학습 허용을 새 V2 비교 허용으로 해석하지 않는다.

## 5. 선택 후속 P-010: 저장 예측으로 개선의 안정성을 한 번 확인

R4의 작은 순개선과 R3의 8월 집중이므로 **새 학습 없이 가능한 이 검토는 권장한다.** 다만 P-006의 기존 통과 판정을 다시 만들거나 제출 전 필수 EDA를 늘리는 작업은 아니다. 목적은 확신의 수준과 남길 한계를 판단하는 것이다.

실행한다면 다음 범위를 먼저 고정한다.

1. R3/R4의 저장 B3/P-006 예측, 같은 고정 주 표본과 정답/가격/구성을 사용한다. R3 224개소, R4 252개소를 유지한다. 전체 253개소로 바꾸거나 정답 결측을 0으로 채우지 않는다.
2. 각 시각에서 `d_t = SMP_t × k_t × Σ_g (|Σ_i e_P006,i,t| - |Σ_i e_B3,i,t|)`를 만든다. 잔차는 예측-정답이다. 음수는 P-006 개선이다. 먼저 합계가 기존 전체 W 차이와 맞는지 검산한다.
3. 대상 날짜 s=ts-1시간으로 구간 시작부터 고정 7일 블록을 만들고, 14일은 민감도 확인 한 가지로만 둔다. 끝의 짧은 블록도 삭제하지 않고 길이를 명시한다. 두 모델과 모든 발전소/집합에 같은 시간 경계를 적용한다.
4. 전체 블록의 비용 차이, 악화 블록 수, 가장 큰 개선/악화 블록과 각 블록 하나를 제외했을 때 남은 W 차이의 부호를 전부 기록한다. 제외 결과는 스트레스 점검이고 새 평가 표본/채택 점수로 사용하지 않는다. 좋게 보이는 블록 길이나 날짜만 고르지 않는다.
5. G1/G2와 k=1/3의 비용 차이는 같은 표본에서 함께 보되 새 보정 계수, 혼합 비율, 계절별 모델 정책을 추정하지 않는다. 블록 제외 후 참조 W가 0이면 변화율을 정의하지 않는다.

위 검토는 블록별 기술 요약이다. 난수 재학습, 부트스트랩 신뢰구간, 유의성 검정이나 새로운 독립 검증은 아니다. 발전소를 독립 표본처럼 섞거나 V1/R3/R4의 겹치는 시각을 합쳐 표본 수를 늘리지 않는다.

| 결과 | 해석과 종료 판단 |
|---|---|
| 특정 블록 하나를 빼면 순개선 부호가 뒤집힘 | 개선의 취약성을 기록한다. 개발 기준 통과는 유지하되 최종 우위에 대한 확신은 낮춘다. 좋은 난수나 다른 블록을 찾아 재시도하지 않는다. |
| 7일/14일의 블록 제외에도 방향 유지 | 그 두 분할에서의 안정성 근거를 추가한다. 독립 미래 우위를 확인했다고 쓰지 않는다. |
| 저장 점수와 합계 불일치, 입력/키 오류 | 단순 불확실성보다 우선하는 검증 문제다. 최종 적용을 멈추고 오류를 해결한다. |

현재 월별 표만으로 이 결과를 미리 판정하지 않는다. 취약하더라도 B3가 더 좋다는 증거가 자동으로 생기지는 않는다. 이 분석의 종료는 추가 튜닝 시작이 아니라, P-006을 어느 정도 확신으로 사용할지 설명하는 짧은 결론이다.

## 6. 모델을 바꾸는 후보들의 우선순위

| 방향 | 현재 판단 | 다시 검토할 조건 |
|---|---|---|
| 고정 P-006의 최종 적용 | 가장 우선 | P-009 입력 계약 충족 후 최종 실행 범위를 확정한다. |
| 범주 정규화 강화 | P-003의 선택 세부 후보 | 짧은 이력 ID에서 반복 악화가 확인되고 원인이 단순 미관측/정렬 오류와 구분될 때 한 축만 사전 고정한다. 현재는 과적합을 입증하지 못했다. |
| 미관측 ID의 B3 fallback | 당장 실행할 이유 부족 | 최종 입력에 실제 미관측 ID가 남고 그 처리 정책이 필요할 때 등록한다. 현재 원본/기간에서는 253개소 낮 기록이 있다. |
| B3/P-006 앙상블 또는 집합별 선택 | 보류 | 상보적 오차의 안정성과 별도 비교 계약이 있어야 한다. 현재 결과에서 좋은 그룹만 고르는 것은 사후 선택이다. |
| 집합 손실/부분 풀링 | 장기 선택 후보 | 개별 CF L1과 W의 차이는 남지만 식별/구현/비교 설계가 필요하다. 현재 P-006 통과만으로 다음 최우선이라고 할 수 없다. |
| 학습 기간/난수/트리 수 광범위 탐색 | 보류 | P-003의 제한된 예산과 질문을 별도 확정해야 한다. R4의 작은 차이를 크게 만들기 위한 반복은 하지 않는다. |
| 유형별 모델 분리/전체 기상 요인 대체 | 근거 부족 유지 | DA-012의 불일관성과 DA-001/005의 제한을 바꿀 새 근거가 있어야 한다. |
| 용량/가격 가중 손실과 기존 H1 재시험 | 현재 중복 | B5/B6/H1 이력과 다른 독립 가설이 없으면 반복하지 않는다. |

LightGBM은 작은 범주의 과적합에 `cat_smooth`와 `min_data_per_group` 사용을 설명한다. 이는 방법의 가능성일 뿐 이 데이터에서 값을 키우면 좋아진다는 증거는 아니다. P-006은 이미 기본 범주 정규화를 사용했으므로 이를 처음 추가하는 개선안으로 제시하지 않는다. [LightGBM 4.6.0 공식 문서](https://lightgbm.readthedocs.io/en/v4.6.0/Advanced-Topics.html).

후보 선택에 쓴 자료를 계속 보며 설정을 고르면 독립된 시험 근거가 되지 않는다. 이미 사용한 개발 구간을 새 이름으로 바꾸거나 V2를 다시 보아 이 문제를 해결할 수 없다. [scikit-learn 공식 검증 주의사항](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage).

## 7. 최종 실행 단계로 넘어갈 때의 기준

P-009가 맞고 입력 연결 오류가 없다면 **P-006을 현재 개발 우선 후보로 고정해 최종 적합 1회와 로컬 출력 검증을 준비하는 방향**을 권장한다. P-010은 제한된 추가 설명 근거이며, 독립된 미래 성능 확인을 대신하지 않는다. 이번 요청에서는 어느 후보도 추가 실행하지 않았다.

최종 실행 계약에는 기존 39열+명목 ID, L1/600트리/범주 기본값/낮 선택/목표 clip/출력 처리, 동일 학습 기간과 참조 구성을 유지한다고 적는다. 연중 재학습, 상한 clip, 신규 보정이나 그룹 재배정은 추가하지 않는다. 같은 버전/난수 정책을 기록하고 좋은 seed를 고르는 작업도 없다.

최종 적합 뒤에는 253개소 범주 사전, 40열과 트리 수, 저장 전후/배치 순서 동치, 253×8,760=2,216,280개 개별 키, 2×8,760=17,520개 집합 키, 중복/결측/유한/비음수/야간 처리와 집계 합을 검증해야 한다. 원본 기상 NaN 허용과 출력 NaN 불허는 구분한다. B3 모델/예측과 다른 경로에 저장하고 공식 제출은 별도 요청 범위로 남긴다.

제공 평가에는 정답이 없으므로 P-006 평가 예측과 B3 예측의 차이를 W 개선으로 보고하지 않는다. 출력 검증을 통과해도 가능한 표현은 '최종 적용 산출물 생성과 검증 완료'다. 독립 미래 성능은 미확정으로 남는다.
